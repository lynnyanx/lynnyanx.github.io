## 📖 项目简介

**端子压接缺陷 AI 视觉检测系统**运行于深圳产线：Basler 工业相机采图，**YOLO11m-OBB** 旋转框模型经 TensorRT 加速推理，为每一个压接端子给出标注后的 OK / NG / 需复核 判定 —— 替代原先完全依赖人眼的目检工序。

压接端子的外观缺陷有十余种，人工目检依赖经验、易疲劳，判定口径也因人而异。本系统的应对方式：

- 🎯 **14 类旋转框检测**：OBB 框贴合端子实际姿态，工件倾斜不影响几何判定
- 🔁 **内建数据回流闭环**：每次人工判定与模型检测结果并排落盘，直接成为下一轮微调的训练数据
- ⚠️ **三态判定**：NG / OK / 需复核 —— 产线实测「一个框都不画」的漏检率高达 56%（是画出良品框时的 9 倍），因此对「沉默」升级处理而不是默认放行

### 🔍 缺陷类别体系（14 类）

| # | 类别 | # | 类别 |
|---|------|---|------|
| 1 | 良品 | 8 | 外被压少 |
| 2 | 无喇叭口 | 9 | 外模错位 |
| 3 | 露黄 | 10 | 弹片下陷 |
| 4 | 芯线反折 | 11 | 端子驼背 |
| 5 | 未露芯线 | 12 | 端子后仰 |
| 6 | 芯线过长 | 13 | 防水塞遗失 |
| 7 | 溢胶 | 14 | 防水塞不良 |

> 判定规则：检出任一缺陷 → **NG**；仅有良品框 → **OK**；一个框都没有 → **需复核**（模型两边都不确定，实测最危险的一类输出）。

## ✨ 核心功能

### 📷 采集与推理
- **Basler 工业相机**：pypylon 独立采集线程，相机参数由 `camera_config.pfs` 加载
- **双分辨率链路**：缩放流供连续实时推理；全分辨率原图保留给「拍照检测」单次推理
- **连续 + 单张两种模式**：视频流上实时预测；每次拍照对全分辨率原图单独推理一次（标注字体与线宽随分辨率自适应）
- **相机仿真模式**（`PYLON_CAMEMU`）：无需物理硬件即可运行整个应用，用于开发与回归测试
- **GPU → CPU 自动降级**：推理异常时自动切换，产线不停线

### 🖥️ 产线工作站（Tkinter）
- **拍照 → 确认 → 归档工作流**：定格标注画面，在常显按钮网格上确认或修正缺陷类别，保存后自动返回实时画面
- **单样品多拍**：「存入同一样品」把多角度照片归到同一实体样品；样品编号跨重启持续递增，不复用
- **已存图片复查页**：可重新打开当前样品的任意照片改判（文件自动在 OK/NG 目录间迁移），静态画面支持滚轮缩放、拖拽平移、双击复位
- **防错设计**：「良品」与缺陷标签互斥；保存前校验；最近一次保存可一键撤销；自定义标签需密码授权
- **缺陷优先渲染**：检出任一缺陷时自动隐藏良品框，同一画面不出现互相矛盾的结论

### 📊 数据闭环与评估工具链
- **样品级 JSON 记录**：模型检测（类别、置信度、OBB 坐标）与人工判定同盘存储，一个实体样品一个文件，原子写入
- **产线口径评估**（`evaluate_model.py`）：把每条保存记录回放为「真值 vs 预测」，输出图像级与样品级的召回率 / 漏检率 / 精确率 / 过杀率 —— 与产线关心的口径完全一致
- **冻结测试集**：每次模型更新都在两个模型都没见过的固定图像集上对比
- **可解释性工具**：GradCAM 热力图、遮挡实验（删除 / 保留 / 对照）与盲标协议，同时审计模型与真值质量

## 🔬 模型改进

系统交接时带有一版基线模型。没有采信交接材料上的指标，而是让应用从第一天起就**逐张同时记录模型检测结果与作业员判定** —— 首周累计 358 个样品 / 1,334 张图像，真实性能因此变得可测量：

**基线（产线实测）**：精确率 97.6%，但图像级 NG 召回率仅 **35.6%** —— 三分之二的缺陷图像被放行。对质检而言，漏检才是致命的一侧。

### 定位到的根因

1. **标签-架构错配（关键发现）**——良品框约占整图 70%，超出 YOLO-OBB 框回归的表达上限（DFL `reg_max` × stride）。框被截断到真实尺寸的 54–87%，置信度封顶在 0.8，并出现 35 个重复误报框。**修复**：将良品标签长边收缩到 ≤600 px @1280 → 框质量 mAP50-95 由 **0.58 升至 0.99**，重复框消除。
2. **严重类别失衡与数据稀缺**——良品框 650 个，多数缺陷类 ≤25 个，3 个类别 ≤5 个样本。**修复**：重建数据管线（全量审计、按实体样品 ID 划分防泄漏、稀有类分层），LVIS repeat-factor 过采样，并合并重映射的历史数据集（+516 张），所有稀有类训练实例 ≥140。
3. **微小且被遮挡的关键缺陷**——芯线反折目标极小且被防水塞半遮挡，640 px 推理分辨率不足（召回率仅 3.8%）。**修复**：训练与推理尺寸 640 → 1280，部署模型该类验证集召回率已达 97%（AP50 0.95）。
4. **标注口径缺口**——作业员使用的部分标签并非模型类别，从统计口径上放大了漏检数。**修复**：新增第 14 类、归一同义标签、逐框复核 147 个口径不一的标注，含存疑缺陷的图像一律整图排除（只删框不删图 = 教模型忽略缺陷）。

### 冻结测试集验证

1,008 张来自后续生产批次的图像 —— 两个模型都没训练过：

| 指标 | 基线模型 | 微调模型 |
|------|--------:|--------:|
| 准确率 | 71.1% | **85.0%** |
| NG 召回率 | 59.1% | **84.3%** |

### 交付验收 —— 产线实测

交付模型（finetune 20260728，14 类，1280 尺寸，置信度 0.6）在 **8,224 张产线图像 / 2,060 个实体样品**上完成验收 —— 数据采集于 2026-07-31 ~ 08-01，全部在训练截止之后，无数据污染：

| 验收指标 | 结果 | 客户要求 |
|---|---:|---|
| 样品级 NG 检出率 | **99.6%** | ≥ 95% ✅ |
| 单张 NG 检出率 | **96.08%** | ≥ 95% ✅ |
| 整体准确率 | **99.56%** | ≥ 95% ✅ |
| 过杀率 | **0.146%**（每千张约 1.5 张） | — |

2,060 个样品中唯一漏判的一个，其标签为「其他瑕疵」—— 不在 14 个训练类别之内，属结构性不可检。指标直接由存档的 `model_detections` 统计得出，未重跑推理。

### 盲复核 —— 连真值本身也要审计

作业员标注时画面上同时显示着模型的检测框，判定会被锚定。对全部 64 组模型-人工分歧做了不看模型结果的盲复核，并以 24 组本来一致的样本做对照（100% 复现，证明盲判可信）。结果：**模型在 44% 的分歧中是对的** —— 被记为「漏检」的 49 张里有 24 张是作业员锚定下的多标，被记为「过杀」的 15 张里有 4 张是模型先发现的真缺陷。盲裁决后单张 NG 检出率由 92.5% 修正为 96.1%，精确率由 97.6% 升至 98.2% —— 锚定标注一直在*低估*模型。

## 🚀 运行与部署

### 环境要求

- **产线侧**：Windows 10/11，Basler 相机 + pylon 运行时（或仿真模式），Python 3.12（uv 管理）
- **训练侧**：GCP Linux GPU 实例（2× A100），PyTorch cu128

### 常用命令

```bash
# 产线应用
uv run main.py

# 新机器上重建 TensorRT engine（engine 与机器绑定）
python build_engine.py app_folder/weights/<model>.pt

# 微调 / 评估
python train.py
python evaluate_model.py --from <date>   # 产线口径评估报告
python eval_image_level.py               # 冻结测试集图像级指标
```

> **TensorRT engine 与机器绑定**：`.engine` 文件只匹配构建它的 GPU + TensorRT 版本。`build_engine.py` 的存在是因为 Ultralytics 自带的 `export(format='engine')` 在 TensorRT 11 上失效（`EXPLICIT_BATCH` 标志已移除）—— 它改为先导出 ONNX，再用 TensorRT Python API 构建 engine，并补上 Ultralytics 读取 engine 所需的元数据头。

## 🛠️ 关键设计决策

### 在产线上测量，而不是采信交接材料
应用为每一次检测同时记录模型检测与人工判定。基线模型 35.6% 的真实召回率在其训练指标里完全不可见 —— 正是因为生产数据从第一天起就兼作评估集，问题才浮出水面。

### 让标签匹配架构
最有价值的修复不需要任何新数据：良品框尺寸超出了 YOLO-OBB 框回归的表达上限（DFL `reg_max` × stride）。识别出这是「架构施加的标签约束」，让一个看似噪声很大的模型变得行为端正（mAP50-95 0.58 → 0.95）。

### 沉默不等于安全
「一个框都不画」的实测危险性是画出良品框时的 9 倍。系统没有把沉默映射为 OK，而是升级为第三种判定状态并提示作业员重点复核 —— 这一策略调整的价值超过数个百分点的模型精度。

### 排除歧义，而不是掩盖歧义
标注无法确认的图像整图排除出训练集。只删标注框会让缺陷以「背景」身份留在图中 —— 等于主动教模型忽略它。

### 同时审计模型与真值
GradCAM 与遮挡实验验证模型确实关注缺陷区域，盲标协议检验作业员判定的一致性 —— 指标的两端都被验证，而不只是模型一端。
